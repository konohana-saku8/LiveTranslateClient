# LiveTranslate Client (Android)

把手机里正在播放的声音实时送到电脑上的 LiveTranslate，识别与翻译在电脑端完成，结果同时显示在手机悬浮窗（可选同步到电脑悬浮窗）并写入电脑端的历史数据库。

```
手机（其他应用的音频）
  └─ AudioPlaybackCapture（16 kHz / 单声道 / PCM16LE）
       └─ WebSocket ──► 电脑 LiveTranslate
                           ├─ Silero VAD 切句
                           ├─ ASR 识别
                           ├─ 流式翻译
                           ├─ 写入历史数据库（与电脑本地采集一致）
                           └─ JSON 字幕事件 ──► 手机悬浮窗 / 电脑悬浮窗
```

## 环境要求

- 手机：Android 10 及以上（`minSdk 26`，音频采集依赖 Android 10 的 `AudioPlaybackCapture`）。
- 电脑：LiveTranslate 已启动，且控制面板顶部的「远程服务」处于运行状态。
- 手机与电脑在同一局域网。

## 电脑端准备

1. 打开 LiveTranslate 控制面板，在「服务配置」标签页确认监听地址、端口（默认 `8766`）、访问令牌，以及是否「同步显示到 PC 悬浮窗」。
2. 在电脑端悬浮窗标题栏点击「启动服务」（与「运行 / 暂停」按钮放在一起）。旁边的圆点指示状态：灰色=未启动，黄色=等待手机连接，绿色=手机已连接；服务运行期间按钮变为「停止服务」。
3. 首次启动时 Windows 防火墙会弹窗，请允许「专用网络」访问；若误点拒绝，需要在 Windows 防火墙中手动放行该端口或 python 进程。自动发现使用 UDP `8766`，放行 python 进程即可同时覆盖 TCP 与 UDP；广播被拦截时，手机会回退扫描网段，功能不受影响。

## 手机端使用

1. 安装 `app-debug.apk`。
2. 「自动查找局域网中的电脑」默认勾选，此时直接点「连接」即可：手机会先通过 UDP 广播询问电脑端，拿到地址与端口后自动连接，无需手动填写。访问令牌仍需与电脑端「服务配置」一致。
   - 想手动指定地址时，取消勾选，填写局域网 IP 与端口后再点「连接」。
   - 找不到电脑时，确认电脑端已更新到带「自动发现」的版本；旧版电脑端不支持广播，手机会回退扫描默认端口 `8766`，若电脑端改过端口则取消勾选并手动填写。
3. 点击「开始」，完成授权：
   - 录音权限、通知权限；
   - 「显示在其他应用上层」（悬浮窗）；
   - 系统屏幕捕获弹窗——在「应用范围」中选择要采集的应用，或选择整个屏幕。
4. 悬浮窗出现后开始播放目标应用的声音，即可看到原文与译文。

> 「连接」只负责与电脑建立连接；「开始」只负责选择投影应用并启动音频采集。断开连接会同时停止正在进行的采集。

> 屏幕捕获只用于获取应用播放的音频，不会录制或上传画面。

## 悬浮窗

- 拖动：标题栏空白处（标题、状态文字、右侧空白均可拖动）。
- 缩放：拖动右下角的缩放把手。
- 按钮：`清空`、`设置`（回到设置页）、`停止 / 继续 / 开始`。
  - 采集中点击「停止」→ 暂停推流并断开连接，状态变为「● 已暂停」，按钮变为「继续」；
  - 点击「继续」恢复推流；
  - 采集已完全结束时按钮显示「开始」，点击会打开设置页重新授权屏幕捕获。
- 状态指示：`● 已连接 · zh` 表示已连上电脑，`zh` 为电脑端当前的目标语言代码。
- 位置、尺寸会自动记住。

## 数据与入库

手机端的处理结果与电脑本地采集使用**相同的入库策略**：

- 每句翻译完成后写入电脑端历史数据库（源文 + 译文 + 目标语言）；
- 翻译失败也会写入，译文使用失败占位符并标记为失败，避免丢失原文；
- 原文与目标语言相同（无需翻译）时不写库；
- 数据库路径与「调试数据库」开关仍由电脑端控制面板决定。

## 构建

构建需要 JDK 25（Android Studio 自带的 JBR 即可，把 `JAVA_HOME` 指向它）：

```powershell
cd LiveTranslateClient
.\gradlew.bat :app:assembleDebug
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

产物：`app/build/outputs/apk/debug/app-debug.apk`。

## 权限说明

| 权限 | 用途 |
| --- | --- |
| `RECORD_AUDIO` | 捕获应用播放的音频 |
| `POST_NOTIFICATIONS` | 采集前台服务通知（Android 13+） |
| `SYSTEM_ALERT_WINDOW` | 显示悬浮字幕窗 |
| `FOREGROUND_SERVICE` / `FOREGROUND_SERVICE_MEDIA_PROJECTION` | 保持采集在后台运行 |
| `INTERNET` / `ACCESS_NETWORK_STATE` | 连接电脑端服务 |
| `ACCESS_LOCAL_NETWORK` | Android 17 起访问局域网设备所必需；未授权时连接会超时 |

## 通信协议

- 自动发现：手机向 `255.255.255.255:8766`（同时向各网卡的广播地址）发送 UTF-8 文本 `LIVETRANSLATE_DISCOVER_V1`；电脑端回复 JSON：

  ```json
  {"app": "livetranslate", "protocol": 1, "port": 8766, "token_required": false, "name": "PC-NAME"}
  ```

  `port` 是电脑端实际监听的 WebSocket 端口，因此改过端口也能自动找到；令牌本身不会广播。未收到回复时，手机回退扫描本网段（/23 或更小的网段）的最后已知端口。
- 地址：`ws://<电脑IP>:<端口>/ws/subtitle?token=<令牌>`
- 上行：二进制帧，原始 PCM16LE、16000 Hz、单声道。
- 下行：JSON 文本帧

| 事件 | 说明 |
| --- | --- |
| `ready` | 握手完成，携带 `sample_rate`、`target_language` |
| `asr` | 识别结果：`text`、`language`、`asr_ms`、`timestamp` |
| `translation_delta` | 流式翻译增量 |
| `translation` | 最终译文：`text`、`tl_ms` |
| `error` | 错误信息 |
| `pong` | 心跳响应 |

同一时间只允许一台手机连接；重复连接会以业务码 `4409` 被拒绝，不会踢掉已连接的设备。

## 常见问题

**连接一直转圈或提示连接断开**

- 保持「自动查找」勾选时，手机每次点「连接」都会重新广播寻找电脑，电脑 IP 变化无需任何设置。
- 确认手机与电脑处于同一网段，且能互相访问（部分路由器的「AP 隔离 / 访客网络」会阻止设备互访）。
- 电脑端「远程服务」是否已启动，令牌是否一致。
- Android 17 必须授予「本地网络」权限（首次点击「连接」时申请）；被拒绝后可在系统设置中手动开启。
- 设置页是否显示「已连接」；「开始」在未连接时会提示先连接。
- Windows 防火墙是否放行了该端口/进程；自动发现需要 UDP `8766`（放行 python 进程即可）。
- 提示「未找到电脑」时，若电脑端是旧版本（没有自动发现），手机会回退扫描默认端口 `8766`；改过端口则取消勾选手动填写，或改用新版电脑端。

**提示「访问令牌不正确」**

- 点「连接」后自动发现成功、但电脑端设置了令牌时，手机端令牌必须与电脑端「服务配置」中的值完全一致。

**悬浮窗没有字幕**

- 部分应用禁止被捕获（受版权保护的音乐、通话等），此时没有音频输入。
- 在系统弹窗中选择了「共享一个应用」时，只有该应用的声音会被采集。
- 电脑端 ASR 模型是否已加载完成，日志中是否有识别结果。

**更换电脑 IP 或令牌后**

保持「自动查找」勾选时无需任何操作，重新点「连接」会重新发现电脑。手动模式下修改设置页字段后重新点「连接」；悬浮窗设置按钮可直接回到设置页。
